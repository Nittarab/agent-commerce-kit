A controlled way for agents to buy services

Give agents a task.
Keep control of the money.

We are building an SDK that lets an agent agree on a service, pay for it, and recover the result — within rules set by its owner.

Poppy · identity and approvalx402 · payment over HTTPNEAR testnet · token transfer

Example: a research agent buys a report. A reviewer buys a check. Both use one budget. A timeout must not make either agent pay twice.

Three protocols. Three distinct jobs.

01 / AGREE

Poppy

Identifies the agent and user. The supplier describes an operation with exact terms and a revision. The agent approves those terms under the owner's policy.

02 / REQUEST PAYMENT

x402

The supplier replies with HTTP 402: the token, amount and recipient needed to unlock the service. The client returns a signed payment authorization.

03 / SETTLE

NEAR testnet

A separate relayer submits the authorized transfer. We inspect the final inner token-transfer receipt before calling the purchase paid.

The policy is enforced outside the model

The model can propose a purchase. It cannot select a different payer, increase its budget, or tell the controller to skip approval.

Private code. Public testnet receipts.

The repository and this local page stay private. Blockchain accounts and transfers are visible on NEAR testnet. We use fresh test accounts and faucet tokens, not mainnet funds.

No keys, authentication tokens or signed payment payloads are included in this page.

The first live scope is a signed-out Poppy API with Operations v3, one supplier, ed25519 keys, and the wrap.testnet token. General conversations, OAuth, arbitrary suppliers, multichain payments, production custody and a live model are later work. If a payment expires after signing but before the supplier first records it, automatic recovery is limited and the money remains held. Failed or unknown transfers also stay held for manual analysis. The live driver runs buyer, supplier and facilitator in one trusted host process.

How the code fits together

ModuleResponsibility
policy + ledgerDecide, reserve funds, remember the exact attempt, and retain uncertainty.
wallet + NEAR adapterKeep keys on the host, sign the approved transfer, and inspect chain evidence.
Poppy + x402Authenticate, bind the operation approval, and carry payment headers.

supplier + facilitatorCheck the request, relay the transfer, and return the purchased result.
